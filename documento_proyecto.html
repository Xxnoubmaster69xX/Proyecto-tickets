1. Arquitectura del Sistema (MVC)

El sistema se construyó bajo una arquitectura altamente escalable separando drásticamente el Cliente (Frontend) del Servidor (Backend), respetando rigurosamente el patrón Modelo-Vista-Controlador (MVC).
(💡 Pasa el ratón sobre los módulos del diagrama para ver su justificación técnica)

Patrones de Diseño Implementados
  • Singleton: Instancia global y única de conexión a SQLite aislada por hilos de ejecución para evitar bloqueos por concurrencia.
  • Repository Pattern: Aísla el código SQL de los Controladores. Todo acceso a la Base de Datos se hace mediante interfaces abstractas.
  • Observer (Event Bus): Emite eventos asíncronos entre componentes cuando los administradores modifican los catálogos.

3. Lógica de la Aplicación: Interfaz Pública (Tickets)

El flujo de atención a padres de familia permite solicitar y emitir turnos independientes por Municipio, calculados algorítmicamente. Además, integra un Módulo de Consulta Pública que permite buscar un turno usando solo la CURP, y reimprimir el ticket en un archivo PDF renderizado a nivel píxel mediante la API de Canvas. 

                sequenceDiagram
                    actor Padre as Padre/Tutor
                    participant UI as Ventanilla Pública
                    participant API as Backend (FastAPI)
                    participant DB as Base de Datos

                    Padre->>UI: Ingresa CURP y Datos Personales
                    UI->>UI: Validación RegEx Oficial CURP (18 caracteres)
                    Padre->>UI: Elige Municipio, Nivel y Asunto
                    Padre->>UI: Clic en "Generar Ticket"
                    UI->>API: POST /api/solicitudes (JSON)
                    API->>DB: Registra o actualiza al Alumno
                    API->>DB: Calcula Turno MAX() + 1 para ese Municipio
                    DB-->>API: Nuevo Turno Generado
                    API->>DB: Inserta la Solicitud y Vincula Relaciones
                    API-->>UI: 200 OK + Ticket en JSON
                    UI-->>Padre: Muestra Número en Pantalla
                    Padre->>UI: Clic en "Descargar Comprobante PDF"
                    UI->>API: GET /api/solicitudes/{id}/pdf
                    API-->>UI: Buffer Binario PDF (Generado Dinámicamente)

4. Lógica de la Aplicación: Panel Administrativo

El sistema incluye un submódulo protegido que permite al personal de la universidad y directivos gestionar, auditar y resolver las solicitudes ciudadanas a través de un Dashboard y herramientas CRUD.
